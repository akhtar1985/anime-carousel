How anime-carousel compares

There is no “best” carousel library — there is a best fit. This page compares built-in features so you can decide quickly, and it is candid about where the established libraries are stronger.

13 built-in modes loop without clones MIT one peer dep: animejs@^4 no build step
How to read this page

Capabilities change between majors. The table describes default, built-in behaviour as of late 2026 — not what community plugins or custom code can add. A dash (—) means “not built in”, not “impossible”. Check each project’s current documentation before you commit.

Who should use it — and who shouldn’t

Good fit

  • Static sites, landing pages and documentation that want depth effects without a bundler.
  • Shopify themes and CMS embeds — Liquid or a CMS block plus an import map is enough; there is no build step.
  • Teams migrating off Slick — the option vocabulary is intentionally compatible, but there is no jQuery and no clone-slide loop.
  • React / Vue / Svelte apps that only need the carousel as an imperative instance (one ref, one effect), not another wrapper to maintain.
  • Music, photo and portfolio sites where wheel / helix / fold / zoom motion is the point.
  • Anyone already using Anime.js who wants the carousel on the same animation engine, easing vocabulary and spring physics.

Pick something else when…

  • You need official React / Vue / Svelte components with SSR-safe rendering. Swiper, Splide and Embla ship maintained wrappers.
  • You virtualise thousands of slides. This plugin keeps every slide in the DOM (like Slick, Splide and Glide). Swiper’s virtual slides module is built for large data sets.
  • You want only free-scroll physics. Embla is smaller and focuses entirely on drag momentum.
  • You need IE11 or very old Safari. This is modern ESM with CSS 3D and inert; Slick is the retro option.
  • You need a plugin marketplace. Swiper and Splide have years of ecosystem ahead of this project.

What is genuinely different here

1. Thirteen modes, not just “slide and fade”

The engine projects every slide through the same geometry snapshot, so each mode is a pure (distance, options) → transform state function. That is why the unusual modes are small and composable instead of separate plugins:

slide · fade · coverflow · cards · wheel · helix · flip · fold · cube · zoom · marquee · kenburns · staggered

See The 13 modes, in depth for defaults, tuning and use cases.

2. Effect studios instead of one fixed preset

Coverflow, wheel and helix are small layout engines. Every value is applied per slide distance, so the active slide is untouched and neighbours reshape live:

Mode Layout knobs
coverflow rotate, depth, scale, modifier, opacity, offset, tilt, lift, blur, visible
wheel radius, angle, scale, opacity, offset, depth, tilt, blur, visible
helix radius, rotate, rise, scale, opacity, offset, depth, tilt, blur, visible

Swiper’s coverflow exposes rotate, stretch, depth, modifier and shadows. The tilt, lift, blur and visible controls — and the same vocabulary on wheel and helix — are unique to this plugin. The demo ships live studios for all three.

3. Virtual loop, logical indices

Infinite loop is modular index maths over a progress value, not cloned DOM. There is nothing to style twice, activeIndex stays in 0…n-1, events stay logical, and destroy() has no clones to unwrap. Only marquee duplicates slides, and it removes them on teardown. Embla and Flickity also avoid clones; Slick, Splide, Glide and Swiper’s loop use duplicates.

4. One vocabulary, two ecosystems

Slick and Swiper names are normalised by the same option layer:

Aliases are documented in the main README options table.

5. Same animation engine as the rest of your app

Easing strings, spring: true with createSpring(), stagger() reveals, and the same animate / createTimeline primitives used elsewhere. No legacy anime({…}) syntax and no second animation engine.

6. Runtime setMode()

Switch layouts without destroying the instance:

runtime mode switchingESM
slider.setMode('helix', { helixEffect: { radius: 200, rotate: 30 } });
slider.setMode('coverflow', { coverflowEffect: { tilt: 10, blur: 1.5 } });

The instance keeps its index, listeners, DOM and a11y state. This is what powers the demo’s mode chips.

7. Accessible and reduced-motion aware by default

Roles, per-slide labels, aria-hidden + inert on off-screen slides, a polite live region, roving-tabindex bullets, keyboard support (including RTL and vertical) and instant transitions when prefers-reduced-motion: reduce is set. See the README accessibility section.

Where the established libraries are ahead

Being fair:

  • Ecosystem and maturity. Swiper and Splide have years of issues, answers and third-party extensions. This project is a v1 with a small, readable source base.
  • Framework coverage. Swiper, Splide and Embla ship official React / Vue / Svelte components. Here you mount the instance yourself (see the React recipe).
  • Virtualisation. Swiper’s virtual slides handles very large collections by rendering a window. This plugin renders every slide, like Slick.
  • Free-scroll physics. Embla’s drag engine is more specialised and lighter for momentum-only behaviour.
  • Module breadth. Swiper also ships zoom, grid, parallax and history modules. This plugin intentionally keeps one engine and 13 modes.

If those matter more than animation depth, pick the mature library. If the animation is the product, this plugin removes a lot of bespoke work.

Switching from Slick or Swiper

From Slick

Markup: Slick items become direct children of the slider. The plugin generates .ajc__viewport and .ajc__track wrappers for you (or write them yourself — both are supported).

Gotchas

Remove jQuery and Slick CSS; import anime-carousel/styles. Slick’s .slick-current / .slick-active classes do not exist — the active slide carries .is-active, and slider.activeIndex is always the logical index.

Gotchas

Swiper’s .swiper-wrapper / .swiper-slide markup is not required. Slides are the direct children and the plugin adds .ajc__slide. There is no module import step — effects, a11y, keyboard, mousewheel and controller sync are built in. Loop creates no duplicates, so never style .swiper-slide-duplicate.
